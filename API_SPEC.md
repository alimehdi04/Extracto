# Extracto API & Data Specification (v1.0)

Extracto operates as an asynchronous, event-driven system rather than a traditional synchronous REST API. The entry point is an AWS S3 `PUT` event, and the exit point is a DynamoDB table record.

---

## 📡 Endpoints (Event Triggers)

### `PUT` /s3://extracto-docs-alimehdi-2026/{document_id}
**Description:** Uploads a document to the cloud storage bucket, initiating the AI analysis pipeline.

#### Parameters
| Name | Located in | Description | Required | Schema |
| :--- | :--- | :--- | :--- | :--- |
| `document_id` | path | The unique filename (e.g., `resume_2026.txt`). | Yes | string |
| `file_content` | body | The raw binary or text data of the document. | Yes | string (binary/utf-8) |

#### Expected Behavior
*   **Status 202 (Accepted):** The file is successfully stored in S3, and the asynchronous Lambda execution is triggered in the background.

---

## 💾 Data Models (Database Schema)

Once the backend finishes processing the S3 event, it exposes the resulting data in Amazon DynamoDB. A downstream frontend (e.g., Next.js, React, or Flutter) can query this table using the original `document_id`.

### `ExtractoResults` (DynamoDB Table)

**Partition Key:** `document_id` (String)
